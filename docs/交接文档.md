## 1. 这条线负责什么、不负责什么

**负责**：PHL 自己这个 Electron 程序的全部 —— 界面、本地数据读写、与 phix 服务端的同步、
应用内自动更新、打包与发布。

**不负责**：

- **Pinghe Launcher Lite（PHL Lite）**：那是 `D:\phl-lite-dev`，Python + pywebview 的另一套实现，
  已经拆成独立开发线。两边**共用一份本地数据**（见 §6），但代码互不依赖。
- **phix 服务端 / 官网**：`D:\phix\server`、`D:\phix\website`。
- **心履**：`D:\moodsite\*`（PHL 只通过自己的 REST 客户端读心履，不改它的代码）。

**与 PHL Lite 的耦合点有三类**：① 共享磁盘格式；② 运行标记/心跳格式（这两类必须
两边一起改的公共接口，本文 §6 与 `docs/共享数据与进程互斥.md` 讲清楚了）；
③ **逐字节相同的登录界面** `src/account-ui.js`（改它必须同步改
`D:\phl-lite-dev\ui\account-ui.js`，有测试守着）。`src/account-bridge.js` 是 PHL 自己的
宿主桥，两边**不同**，不要以为也共用；PHL 的配色/动效/明显跳过入口放在
`src/account-theme.js`（只增强 PHL 副本，共享文件一个字节都不改）。

## 5. 调用的服务端接口

phix（`https://phix.ing`，局域网 `192.168.5.41:8931`）：

| 用途 | 端点 |
|---|---|
| 登录/注册/续期/改密/恢复/密钥材料 | `/api/v1/auth/*`（`login`、`register`、`refresh`、`password`、`rewrap`、`recover`、`keymaterial`、`me`、`devices`） |
| 清单 / 读写对象 | `/api/v1/sync/manifest`、`/sync/objects/<name>`（客户端有 `batch()` 封装，但当前同步是逐对象推送，批量接口未启用） |
| **长轮询** | `GET /api/v1/sync/watch?cursor=` |
| 应用内更新 | `GET /api/v1/update/check?product=phl&platform=win|mac` |

心履是**另一套服务**（`https://xin-lv.com/api/v1/`，`electron/xinlv-client.cjs`），不是 phix。
`/auth/sso/*` 当前 PHL **没有调用**（不要照旧文档以为有跨站免密登录）。

**令牌**：登录/注册响应里带 `access_token`（15 分钟 Ed25519 JWT）与 `refresh_token`
（30 天、用一次换一次）；`electron/phix-session.cjs` 落三键（`phix:token` 兼容、
`phix:access_token`、`phix:refresh_token`），`cloudsync.cjs` 在 `token_expired` 时自动
续期并重试原请求一次，续期失败不重试。`bad_credentials`（输错）与 `unauthorized`（登录失效）
要分开处理。

**权威文档**（不要照抄，改协议先改它们）：

- `D:\phix\server\docs\协议规范.md` —— 密钥链、认证、同步协议、限额与错误码
- `D:\phix\server\docs\同步实时化.md` —— 长轮询的完整设计（三种回包、名额、为什么不用 WebSocket）

**长轮询有一条最容易写错的规矩**：`changed=false` 有两种含义相反的情况 ——
**没有** `retry_after` 是正常超时（立刻再挂），**有** `retry_after` 是服务端名额满了
（必须先等）。前者当后者处理会丢延迟，后者当前者处理会热循环打服务器。

## 6. 本地数据

数据根目录的解析顺序、共享/私有文件清单、写入规矩，**以 `docs/data-format.md` 为准**。
要点：

- 两个程序**故意共用** `settings.yaml`、`Schedule`、`Timetable`、`School`、`agent/`；
  各自的私有数据在 `phl/`（本方）与 `phll/`（对方）。
- 数据根默认是 `<程序目录>\data`（不是 `%APPDATA%`；PHL 自己的 Chromium profile
  也在 `data/phl/profile`）。解析顺序：`PHL_DATA_DIR` → `data-root.txt` 记录的目录 →
  `<exe 目录>/data`。
- **两个程序不能同时运行**：同时写共享文件会互相覆盖。用
  `.phl-running` / `.pll-running` 标记 + 30 秒心跳 + 90 秒过期判定来拦。
  完整协议、判决顺序、手工排查、以及一个刚修掉的跨语言格式坑，见
  **`docs/共享数据与进程互斥.md`** —— 改互斥逻辑之前必须读它。
- **PHL 的私有数据当前是明文容器，不是密文**：`phl/launcher.json` 是 `PLAIN1:` +
  base64(JSON)，`phl/ai-history.json` 是 `PHAIH1:` + base64(JSON)，`phl/school.json`
  是 `PHL-SCHOOL-1:plain:`。这是 2026-09-10 起"与共用数据/其他端对齐"的既定选择
  （`main.cjs` 的 `DATA_ENCRYPTION = false`）。旧文件里 launcher 的 `ENC1:` 与 AI 历史的
  旧加密格式仍能读；`school.json` 的旧 `PHL-SCHOOL-1:enc:` **当前不读**（没有传
  `safeStorage`，下次同步重写成明文），见 `docs/data-format.md` §6。
  不要把它当成"已加密"来宣传；也不要随手打开加密，否则会挡住旧文件迁移与两端互操作。
- 账号（三个学校网站 + phix 登录）现在**只认共用 `settings.yaml` 的 `accounts` 段**；
  旧的 `phl/credentials.json` 只做一次性迁移留档，不再作为存储。

## 7. 开发思路与约定

- **注释和提交信息都用中文**，而且习惯写**为什么**（这个代码库里到处都是
  "为什么这么写 / 以前怎么写错的"的说明，照着做）。
- 错误处理的原则是**如实**：取不到就说取不到，不要把"失败"说成"没有更新"
  或者静默降级成空数据。
- 主进程与渲染进程之间**只通过 preload 暴露的白名单方法通信**，不要在渲染进程里
  直接碰文件系统或拼 shell 命令。
- 测试用 `node:test`，写的是**行为**而不是实现细节；涉及外部进程/文件的地方用临时目录。
- 共享 `settings.yaml` 用 `replaceBlock` 做**按段替换**，写盘一律"临时文件 + rename"。
- 版本号只有一个来源：`package.json` 的 `version`（更新检查、关于软件都读它）。

## 8. 已知的坑与禁忌

1. **共享文件不要整份重写** —— 会把 PHL Lite 刚写的段覆盖掉。按段改。
2. **数据根目录的解析顺序动不得**（除非两边一起改）：改了可能让两边指向不同目录，
   用户的"共享数据"会悄悄变成两份。
3. **运行标记格式是跨语言接口**：两边**都要写 camelCase + snake_case 两种拼法、
   读两种拼法**。只认一种会让跨程序的心跳失效（2026-10-12 实测确认并修复，
   测试在 `tests/app-mutex.test.cjs`）。
4. **`manualCheck()` 的"检查失败"绝不能显示成"已是最新版本"** ——
   断网时谎报"已是最新"会让用户以为自己没落后。
5. **`DATA_ENCRYPTION = false` 是故意的**：`settings.yaml` 必须让 PHL Lite 与网页端
   直接读，不能加密；私有 `phl/*.json` 也沿用了明文容器（见 §6）。改回加密前先确认
   旧文件迁移、两端互操作和备份导出都还成立。
6. **登录类操作不要自动重试** —— ManageBac 会锁号；作业/帖子提交的 POST 也不自动重试，
   失败就如实说"未核实"，不要显示成"已提交"。
7. macOS 产物**未签名/未公证**（ad-hoc）：用户点「重启并安装」后由软件自己替换，
   第一次打开可能需要在"隐私与安全性"里允许。
8. 本机上 `mvn` 不在 PATH（心履那边要用 IDEA 自带的），PHL 这边用 npm 即可。
9. **PowerShell 脚本的编码要分清执行环境**：Windows PowerShell 5.1 会按 ANSI 读无 BOM
   的中文脚本（乱码），要用它执行就得存成 **UTF-8 带 BOM**；本仓库现有的
   `scripts/package-*.ps1` 是 UTF-8 **无 BOM**、含中文，按 `pwsh 7` 运行没问题。
   而 `data-format.md` 里"UTF-8 无 BOM"的规则说的是**数据/源码文件**，不包括"给 5.1 跑的脚本"。
10. 发布/更新走统一流程：产物落到 `release\` 后交给 `D:\phix\_recon\publish_all.py` 等，
    **不要自己直接传服务器**，那会绕过下载页/更新清单的一致性检查。
11. **`phix.ing` 的 Cloudflare 回源**：2026-11-08 发布时隧道 QUIC 数据面持续超时
    （precheck 通过但 `Serve tunnel error ... no recent network activity`，公网表现为 502），
    已在服务器 `/etc/systemd/system/cloudflared.service.d/override.conf` 用
    `Environment=TUNNEL_TRANSPORT_PROTOCOL=http2` 强制 HTTP/2 并重启 `cloudflared` 修复。
    以后再遇到 phix.ing 502：先在服务器上 `curl 127.0.0.1:8940` 确认站点本身正常，再看
    `journalctl -u cloudflared`；不要先怀疑官网代码。
12. **`/media/downloads/` 的稳定文件名会被 Cloudflare 缓存**：更新安装包后，不带 query 的
    旧 URL 可能仍返回旧包。下载页由 `server.py` 自动追加 `?v=<sha12>`，用带 `?v=` 的 URL
    验证；`checksums.txt` 与页面哈希才是事实来源。
13. **phix 账号/同步的界面状态只能沿“一条通知链”刷新**：`phix:*` IPC 统一返回
    `{ ok, data }`，`src/account-bridge.js` 必须解包装（否则设置页账号卡片恒为未登录、
    方向页恒 0 项、准备清单退化成一条假步骤、密码错了也当成功）。主进程在**任意入口**
    （账号向导 / 设置里登录 / 后台自动同步 / 退出）落盘后都会发
    `credentials:changed`、`data:changed`、`phix:changed`；渲染进程
    `refreshAfterPhixChange()` 据此重画所有页面。改同步逻辑时别绕过这三条广播，
    否则又会出现“A 页面未登录、B 页面已登录”。
14. **`settings.ai` 的两个坑**：① 它现在默认参与同步（旧默认对象集合会在
    `loadConfig()` 时自动升级）；本机老 Key 只躺在 secureStore 里时，登录/恢复后由
    `migrateLocalAiToSharedSettings()` 补进 settings.yaml，否则云端永远没内容可拉。
    ② 空 AI 配置序列化**不能**盖 `updated_at = now`，否则每轮 collect 都变、云端
    revision 空涨（`serializeAiConfig` 已处理）；云端有配置而本机是“关闭”时，会自动
    投影成 API 连接并启用。

## 9. 还没做的 / 建议下一步

- `src/app.js` 太大，可以考虑拆分（纯重构，风险要自己评估）。
- 目前只出 Windows / macOS；Linux 未支持。
- 上游 `XKRyan/PH-Launcher` 的关系已基本理清：v2.0.0 已通过 PR #10 合入上游 main 并发布；
  之后的改动仍按"推 `mine` + `origin`"的既有约定执行，是否回贡献上游要看改动性质。
- `docs/` 里有一批历史版本的更新说明，可以整理归档；`docs/` 中的版本号、测试数
  只代表核对当时的状态，改动后要随手更新。
- 真实学校提交作业、回复讨论、发信仍只做过合成数据/测试邮件验证，没有用真实账号跑过。
- 与 PHL Lite 的字节级互操作测试需要 `PHL_LITE_DIR` 指向另一仓库（`tests/account-ui.test.cjs`）。
- **已知缺陷（2026-11-02 核对，未修；细节见 `docs/data-format.md` §11）**：
  - 数据目录指针 `data-root.txt` 的写入位置（`<数据根>/phl/profile/`）与启动时读取
    位置（`%APPDATA%\ph-launcher`）不一致，所以"改用 Lite 的数据目录 / 恢复本应用目录"
    两个按钮重启后不生效。改动涉及数据根解析顺序（两边共用接口），要先定方案再加测试。
  - 旧 profile 迁移（`migrateProfile`）拿到的 `userData` 已经被改向到
    `<数据根>/phl/profile`，直接从 1.0.7 及更早版本升到 v2 的用户不会被自动迁移。
  - 选课 `lessons` 有内容、但当前课表零匹配时，`selectionKeys` 返回 `[]` 被当成
    "用户取消全部"，会清空已保存的教学组。
  - 删除最后一个平台账号时 `SharedAccountStore._write` 提前 return，旧条目留在
    `settings.yaml` 里。
  - `Timetable` / `agent/` 是整文件重建，PLL 写在里面的未知字段会丢；
    linked 日程的更新是最后写入者胜（只有删除有所有权保护）。
  - 共享目录只读时没有界面提示；AI 会话镜像失败时 `saveSession()` 仍返回
    `shared: true`。
  - 设置页"共用数据"说明只列了 settings.yaml/Schedule/agent 三项（实际还有
    Timetable/School），而且英文界面里这段运行时文案仍是中文。
- **已知不一致（待产品决定）**：`phl_auto_login` 会被写进 `settings.yaml`，但当前
  `SharedAccountStore` 只要账号+密码齐备就允许后台自动登录，界面上的"允许自动重新登录"
  开关不改变实际行为（见 `docs/data-format.md` §3.2 / §11）。
