# PH Launcher 系列 · 共存规范：共享的本地数据与进程互斥

> 适用：**PH Launcher（PHL）** 与 **Pinghe Launcher Lite（PHL Lite）**
> 两份实现：`D:\phl-dev\PH-Launcher`（Electron/JS）、`D:\phl-lite-dev`（Python/tkinter）
> 本文最后核对：2026-10-12
>
> 本文只讲**两个程序合用一个数据目录时**的规矩：谁写哪些文件、怎么避免互相覆盖、
> 怎么保证两个程序不会同时跑。
> 目录与文件格式的**细节**在 `data-format.md`（PHL）/ `DATA-FORMAT.md`（PLL）里，
> 本文不重复，只把"两边必须一致"的那部分钉死。
>
> ⚠️ **这两个产品已经拆成两条独立的开发线。** 本文描述的是它们之间**唯一的接口**：
> 磁盘格式 + 运行标记格式。任何一边想改这里的东西，都要**两边一起改、同时发版**，
> 否则用户机器上会出现"一个程序读不懂另一个"的状态。

---

## 0. 一句话

两个程序**故意共用一个文件夹**：账号、选课、日程、课表、学校数据是同一份，
用户在哪个程序里改都一样。代价是它们**不能同时运行** —— 同时写同一批文件会互相覆盖。
所以有一套"运行标记 + 心跳"的握手：谁先起来谁拿到标记，另一个起来时看到标记就不启动。

---

## 1. 数据根目录怎么定

两个程序各自有一套解析顺序，**必须指向同一个目录**才算"共存"。

### PHL（`electron/data-layout.cjs` 的 `resolveDataRoot`）

按顺序取**第一个**候选：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `PHL_DATA_DIR` | 测试、便携启动器、高级用户改向 |
| 2 | 应用配置目录里的 `data-root.txt` 里记的路径 | 用户显式选过就用它 |
| 3 | `<可执行文件所在目录>/data` | 默认。**没有就自动创建** |

> PHL 不考虑 `%APPDATA%`：注释里写明"只有一个架构：程序文件夹里两个 exe + 一个 data/"。
> `data-root.txt` 只是"用户显式改过向"的记录，写入用临时文件 + rename（原子）。

### PHL Lite（`hellopinghe/paths.py`）

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `PHLL_DATA_DIR` | 测试、互通测试用（两个程序的测试脚本靠它隔离） |
| 2 | 安装目录里有 `portable.flag` | 安装器预先写入 → 用 `<安装目录>/data` |
| 3 | 否则 | 历史目录 `~/.hellopinghe` |

> **注意**：PHL **不会**自动去采用 `~/.hellopinghe`（`detectLiteRoot` 只探测、
> 不会自动改向），为的是"不擅自写进别的程序的数据目录"。要共用必须由用户显式选择。

**给开发线的要求**：改这里的解析顺序 = 可能让两边指向不同目录 = 用户的"共享数据"
悄悄变成两份。改之前先确认另一边的行为，并同步更新本文。

## 2. 目录总览：什么共享、什么私有

真实布局（取自 `D:\phl-test\data`，两个程序都装在同一目录）：

```
data/
├── settings.yaml        ← 共享｜账号、选课、界面偏好、AI 配置
├── Schedule             ← 共享｜日程（按天的文件）
├── Timetable            ← 共享｜课表
├── School               ← 共享｜学校数据快照
├── agent/               ← 共享｜AI 会话记录
├── logs/                ← 共享
├── _backups/            ← 共享｜备份
├── _migrated_backup/    ← 共享｜旧布局迁移时的原样备份
├── .sync/               ← 共享｜同步状态（不进云端、不进备份）
├── phl/                 ← **PHL 私有**
└── phll/                ← **PHL Lite 私有**
```

### 共享文件（两个程序都会读写 → 最容易出事）

| 路径 | 内容 | 谁写 |
|---|---|---|
| `settings.yaml` | `accounts` / `lessons` / `ui` / `ai` 四段 | 两边都写（各自只改自己那几段） |
| `Schedule` | 日程 | 两边都写 |
| `Timetable` | 课表 | 两边都写 |
| `School` | 学校数据快照 | 两边都写 |
| `agent/` | AI 会话 | 两边都写（同一份历史） |

### 私有文件（各写各的，互不干涉）

| 程序 | 目录 | 文件 |
|---|---|---|
| PHL | `phl/` | `launcher.json`、`school.json`、`credentials.json`、`ai-history.json`、`state.json` |
| PHL Lite | `phll/` | 对应的私有存储（见 `DATA-FORMAT.md`） |

> `state.json` 这类"上次同步到哪"的**每程序一份**，不能共享 —— 两边各自的同步进度不同。

### 写入共享文件的三条规矩

1. **改自己那一段，别整文件重写**：`settings.yaml` 按段替换（PHL 用
   `settings-yaml.cjs` 的 `replaceBlock`），不要把整份配置读进来再整份写回去 ——
   那样会把另一程序刚写的段覆盖掉。
2. **原子写**：写临时文件 → `rename`。任何直接 `writeFile` 到目标文件的做法，
   在"写一半被杀"时会留下半个文件，两个程序都读不了。
3. **只改内容，不改结构**：段头缩进、键的顺序都要保持，否则另一边的解析器可能认不出。

## 3. 进程互斥：运行标记与心跳

**这是两个程序唯一不能出错的地方。** 同时运行 = 同时写 `settings.yaml` / `Schedule`，
后写的覆盖先写的。

### 3.1 标记文件

| 程序 | 标记文件名 | 写在 |
|---|---|---|
| PHL | `.phl-running` | **共享数据根目录**（不是程序目录） |
| PHL Lite | `.pll-running` | 同上 |

### 3.2 标记格式（跨语言接口，**已冻结**）

```jsonc
{
  "kind": "phl",                                  // "phl" | "pll"
  "pid": 12345,                                   // 写标记的进程 PID
  "startedAt": "2026-10-12T09:00:00.000Z",        // 本应用写 camelCase
  "updatedAt": "2026-10-12T09:00:00.000Z",
  "started_at": "2026-10-12T09:00:00.000Z",       // 同时写一份 snake_case
  "updated_at": "2026-10-12T09:00:00.000Z"
}
```

**两种拼法都要写、也都要认。** 原因见 §5 的踩坑记录：PHL 历史写 camelCase、
PHL Lite 历史写 snake_case，只认自己那一种的话两边互相读不到心跳。
写全两种，新旧版本互相都读得到。

### 3.3 心跳参数

| 参数 | 值 | 含义 |
|---|---|---|
| 刷新间隔 | **30 秒** | 运行期间每 30 秒重写一次自己的标记（`touch`） |
| 过期阈值 | **90 秒** | 超过 90 秒没刷新 → 认为对方已经不在 |

### 3.4 判决顺序（`acquire`）

启动时按这个顺序判，**任何一步命中就弹提示并退出**：

1. **对方在跑？** 读对方的标记 → PID 存活 **且** 心跳新鲜 → 冲突（报对方名字）。
2. **同类在别处跑？** 读自己的标记 → PID 不是本进程 **且** 存活 **且** 心跳新鲜
   → 冲突（同一程序开了两份，但指向同一个数据目录）。
3. 都不冲突 → **写自己的标记**，放行。

### 3.5 怎么判断"PID 还活着"

`process.kill(pid, 0)`（Python 侧用等价的探测）：
没抛异常 = 活着；抛 `EPERM` = **存在但没权限 = 活着**；抛 `ESRCH` = 不存在 = 死了。

### 3.6 心跳判定（`markerFresh` / `_marker_fresh`）

- 标记里**没有**时间戳 → 当作**仍然有效**（保守，兼容老版本写的标记）。
- 时间戳解析不了 → 同样当作有效。
- 否则 `now - updatedAt < 90 秒` 才算新鲜。

> **为什么光看 PID 不够**：PID 会被系统回收给别人。对方崩溃后它的 PID 可能已经属于
> 一个完全无关的进程 —— 这时只看 PID 会误判成"对方正在运行"，于是**程序永远打不开**，
> 用户只能自己去删标记文件。心跳就是为这件事存在的。

### 3.7 退出与刷新

- 运行期间每 30 秒 `touch` 一次。
- **`touch` 和 `release` 都只动自己 PID 的标记**：标记里的 PID 不是本进程时，
  `touch` 直接返回 false、`release` 什么都不删 —— 防止"接管了别人的标记又把它删掉"。
- 正常退出时删掉自己的标记。崩溃/断电时标记会残留，靠 §3.6 的过期判定自动放行。

### 3.8 用户看到的冲突提示

冲突时**不启动**，并明确告诉用户是哪个程序在运行（PHL 会报出
"Pinghe Launcher Lite（PHL Lite）"这种可读名字）。不要静默退出，也不要自动杀对方。

## 4. 手工排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 明明没开另一个程序，却提示"对方正在运行" | 标记残留且 PID 被系统回收给了别的进程 | 删掉数据根目录下的 `.phl-running` / `.pll-running` |
| 两个程序的数据看起来是两份 | 两边解析出的数据根目录不同（见 §1） | 用一个程序里的"改用另一个的数据目录"功能，或设 `PHL_DATA_DIR` / `PHLL_DATA_DIR` 指向同一个 |
| 改完账号在另一个程序里没生效 | 一边整份重写了 `settings.yaml`，把另一段覆盖了 | 见 §2 的三条规矩 |

## 5. 踩坑记录（改这里之前先看）

**① 跨语言标记格式不一致，导致心跳失效（2026-10-12 发现并修复）**

PHL 写 `startedAt`/`updatedAt`（camelCase），PHL Lite 读 `started_at`/`updated_at`
（snake_case），反过来也一样。实测两边**互相都读不到对方的时间戳** →
心跳过期判定在跨程序时等于关掉 → 冲突只剩"PID 还活着吗" →
PID 被回收时会把用户永久挡在门外（正是心跳要防的那件事）。

现在两边**都写两种拼法、读两种拼法**，并各有测试守着
（PHL `tests/app-mutex.test.cjs`、PLL `scripts/test_shareddata_mutex.py`）。
**改标记格式时必须同步改另一边，并跑对方的那个测试脚本。**

**② 不要擅自采用对方的历史目录**

PHL 探测到 `~/.hellopinghe` 也**不会**自动改向 —— 否则会在用户不知情的时候
把两个程序的数据合到一起。共用必须是用户显式选择的结果。

**③ 迁移只复制、不删除**

旧布局迁移（`phl/` 之前的那批 `ph-launcher.*` 文件）一律**复制**到新位置，
源文件不动，并把结果记进 `phl/migrated.json`；重跑是幂等的。
这样升级失败或回退都还能读到原文件。

## 7. 给两条开发线的约定

拆成两条线之后，这个"磁盘 + 标记格式"就是两边**唯一的耦合点**。所以：

1. **改这里要当成改公共接口**：改之前先看对方现在怎么读，改完两边一起发版。
2. **两边都要有测试**：本文提到的两个测试脚本必须保持能跑、能过。
3. **不要各自加私有文件到共享区**：自己的东西放 `phl/` 或 `phll/`。
4. **不要引入新的共享文件**而不通知对方 —— 那等于单方面扩展接口。
5. 真正的跨端数据同步走 **phix 云同步**（见 `D:\phix\server\docs\协议规范.md`），
   本地共享只解决"同一台机器上两个程序看到同一份数据"。
