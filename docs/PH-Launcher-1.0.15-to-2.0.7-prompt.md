# PH Launcher 更新介绍 prompt

将下面整段交给写作 AI，即可生成面向同学的更新介绍：

---

请为 PH Launcher 撰写一篇从 v1.0.15 到 v2.0.7 的中文更新介绍。对象是使用 EduPage、ManageBac 的学生。语气清楚自然，围绕实际学习场景说明变化，不堆技术名词，不夸大为“完全替代学校网站”。先给一个标题和简短导语，再按功能组织正文，最后给出简短升级提示。约 800–1200 字。另附一个适合群聊发送的 150 字版本。

以下是已实现的更新事实：

1. 我的课程成为学校学习入口：课表、课程、通知、任务、讨论、CAS／EE 放在同一工作区。课程内可查看概览、单元与计划、任务、日历、讨论和文件；返回及切换时保留位置，重启后可恢复上次所在栏目、周次及课程。
2. 手动选课及课程关联长期保存，修复重启后恢复自动选择的问题。课表课程可以进入对应 ManageBac 课程查看任务；新增通过当前用户已登录的 ManageBac 会话读取周课表，优先按日期和时间定位课程编号。唯一匹配自动关联，有冲突或网站未提供数据时保留确认和更改入口，已手动更改的关联优先。
3. Assessment、Coursework、Event 统一称为任务。区分任务类型、是否需要提交和实际完成状态；已经发布成绩的测验，包括 0 分，不再因旧提交标签显示逾期。明确要求重新提交的任务仍会提示处理。任务默认按最新时间优先排列，有发布时间时使用发布时间，否则使用任务安排时间。
4. 增加手动刷新及刷新中反馈。学校页面每 5 分钟检查是否需要更新，ManageBac 数据缓存有效期 3 分钟、EduPage 2 分钟；缓存失效不意味着每分钟发起网络请求。后台任务提醒每 10 分钟检查一次，托盘运行时继续工作，完全退出后停止。自动更新复用登录会话，不反复提交密码。
5. 新任务和临近截止提醒可配置，触发应用弹窗及 Windows 系统通知；点击系统通知可进入任务。按任务合并提醒，已完成、已提交或已隐藏的任务移出待办提醒。首次同步不会把历史任务全部当作新任务。Windows 通知的实际展示还受系统通知权限和勿扰设置控制。
6. 任务详情保留正文换行，展示图片和附件；图片可点击放大，文件可从已登录的学校页面打开。图片读取失败时提供原网页入口。日期改为易读形式，全天事件明确标识，优化中英文、窄窗口、滚动及返回操作。上传文件须经过用户确认，上传请求完成并不等于学校确认已提交。
7. 修复同步后出现 `input is not defined`、课程任务读取不完整、慢请求一直等待、旧请求覆盖新课程等问题。网络异常时保留已读取内容，同时提示状态，避免把读取失败说成“没有任务”。
8. 内置背单词入口改为 VLMReader：已安装时直接打开；未安装时展示下载页，默认提供国内 GitHub 中转下载来源，也能选择官方来源。新版移除 PH Launcher 的离线词典入口和随包词库，词汇学习交给 VLMReader；去掉 AI 学习助手旁的“可选”标记。
9. 更新统一 PHL 图标，精简导航、设置及部分弹窗，改善小窗口布局。修复重复云同步连接、错误密码反复自动登录等问题，加强链接、附件和操作来源检查。不要把所有学校账号都描述为加密存储：不同数据的存储方式不同，不能作一概而论的安全承诺。
10. Windows 和 macOS 的 v2.0 打包流程也有调整。不要把本次代码推送写成新版本安装包已经公开发布；以实际 Release 页面为准。GitHub 项目地址：https://github.com/XKRyan/PH-Launcher 。

不要声称修复了全部错误、所有网站结构永远兼容、通知在退出后也有效，或会替用户自动提交任务。不要包含真实用户姓名、账号、班级、课程编号或附件地址。
