# PH Launcher 2.0.14 更新说明

发布日期：2026-11-11

## 与 PHL Lite 1.2.9 共用安装位置和数据

- 安装器会读取 Pinghe 系列的每用户安装登记。检测到 PHL Lite 1.2.9 后，目录页默认采用 Lite 的安装目录和实际数据根；默认值仍可由用户修改。
- PHL 启动后会把自己的实际安装目录、实际数据根和版本写入 `[phl]`，供双方后续安装互相发现。
- 安装登记只用于发现，不改变 PHL 的运行时优先级：`PHL_DATA_DIR` → 固定 Profile 下的 `data-root.txt` → exe 同级 `data/`。
- 升级不会覆盖已有的 `data-root.txt`；卸载只撤销路径匹配的 `[phl]`，不删除 Lite 登记、Lite 程序或任何数据目录。
- 中文安装路径和中文数据路径可无损登记；登记文件保持 UTF-8 无 BOM。

## 数据根与旧版本迁移修复

- 修复设置页切换数据根后，指针写入位置和下次启动读取位置不一致的问题。
- `data-root.txt` 兼容 UTF-8/BOM 与 UTF-16LE+BOM，只接受绝对路径。
- 修复 Electron Profile 改向后旧 Profile 迁移源取错的问题，直接从早期版本升级时仍能复制旧数据。
- “恢复本应用目录”现在正确回到 exe 同级的 `data/`。

## 共享格式兼容

- `settings.yaml` 保存时保留另一端的注释、未知键、嵌套值与对应列表项字段。
- `Schedule` 保持 `{version, kind, app, updated_at, events[], lastId}`，删除当前最大事件后也不会复用旧 id；投影到 PHL 日历时自动补 60 分钟结束时间并封顶 23:59。
- `Timetable`、`School`、`agent/` 写回前读取最新文件并合并未知字段，避免 PHL 与 Lite 任一端升级后被旧数据模型覆盖。
- 所有相关 JSON 写入继续使用同目录唯一临时文件和原子替换。

## 安全与平台说明

- Windows 安装包目前没有商业代码签名证书，系统可能显示“未知发布者”。
- macOS 包为 ad-hoc 临时签名、未 Apple 公证，首次打开可能需要在“隐私与安全性”中允许。
- 卸载不会删除课表、日程、账号、AI 会话或其他用户数据。

## 验证

- Node 自动化测试 1151 项全部通过。
- Windows 真实静默安装/卸载生命周期 19 项检查全部通过，包括中文外置数据根、登记保留和数据不删除。
- Windows 与 macOS 正式产物由同一已审核源码提交构建；发布页提供 SHA-256 与构建证据。
